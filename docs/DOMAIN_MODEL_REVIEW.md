# 领域模型科学研究评审（后续阶段参考）

范围更新：用户已将当前目标收敛为 Study / Features / Runs 管理工具。以 [简化领域模型](DOMAIN_MODEL.md) 为当前设计；本文保留科学验证风险与后续扩展依据，不作为 Step 03–05 工具的前置实体清单。

评审日期：2026-11-06。对象：[DOMAIN_MODEL.md](DOMAIN_MODEL.md)、[工作流](WORKFLOW_STAGES.md)、[共同契约](COMMON_CONTRACTS.md)及当前泛型批次原型。以下是设计评价，不是市场数据实验结论；当时提出的科学对象已在后续简化中延期，没有新增算法实现。

## 1. 总体判断

现有模型适合做可追溯的量化研究执行基础：定义与结果分离、只回看、显式组合、按范围复用、失败留痕和模型定义/拟合分离，均应保留。主要不足是执行对象比科学对象具体：能解释“算了什么、在哪里算”，但尚不足以严谨回答“估计了什么、为什么能推广、这是不是独立证据”。

不建议重写工作流或强制每次走完 events/regimes/hypotheses。应补齐科学证据关系，先作为协议和值对象落地，避免每个概念都独立建表/服务。当前原型仍只有合成算术批次验证；没有真实 L2/catch22、依赖样本推断或独立验证的实现证据。

## 2. 逐项评价与优化

| 方面 | 原设计评价 | 优化后的约束 |
|---|---|---|
| 小批次研究与缓存 | 强，契合用户“先少量再扩大” | 保留；扩展计算范围与改变研究总体分别记录 |
| 合法 feature 组合 | 强，不强制笛卡尔积 | 保留显式选择及依赖闭包；未选、失败、全 NA 分开 |
| 数学定义与物理结果 | 强，但有过度实体化风险 | 保留语义身份；采样轴纳入身份；值对象优先，宽表通过绑定复用 |
| Point-in-time | 原则正确，fit 和事件终态细节不足 | 所有学习变换记录 fit；事件按 as-of 追加观察；训练标签检查可知时间 |
| 研究目标 | 假设有文字，缺少可计算的目标量 | 新增 Estimand，区分描述、关联、预测、因果 |
| 高频样本依赖 | 协议提到区块，但没有实际样本关联 | 新增 SampleDesign/Manifest，保留 episode/日/块与标签支持 |
| 训练与泛化 | 单一 fit 范围不足以描述滚动研究 | EvaluationFold + FitSchedule；区分固定模型与适应策略评价 |
| 适应性搜索 | 有历史，但 Study 边界太弱 | SearchFamily 和数据访问跨批/跨 Study 关联，明确查看/停止规则 |
| 状态识别 | 基本正确，但容易被误读成经济机制 | 记录状态概率、未知/OOD、重训映射；描述稳定性与预测用途分开评价 |
| 证据积累 | 结果留存良好，缺少综合关系 | EvidenceSynthesis 检查重叠、异质性与反证，不能只挑最佳结果 |
| 可交易性 | 原模型未区分清楚 | 统计/经济/执行证据分开；交易假设作为可选扩展 |

## 3. 科学依据与本项目取舍

### 通用统计特征是描述基线

catch22 从跨领域时间序列分类任务中筛选紧凑特征，其研究设计并不是债券 L2 的预测有效性证明。[原始论文](https://arxiv.org/abs/1901.10200)

据此，本项目保留 catch22 baseline 和显式 tsfeatures 扩展，但把采样时钟、缺失、有效覆盖、尺度与算法版本写入定义。在同样样本/验证设计下比较“业务特征”“加 catch22”“再加选定 tsfeatures”；不要求一次计算所有组合。某统计量的稳定性、状态分辨能力与未来收益预测是不同目标，分别报告。

### 时间有序验证要评价整个学习过程

滚动预测原点方法在每个原点用此前数据拟合并评价后续误差，体现了预测时可用信息的限制。[forecast 官方 tsCV 文档](https://pkg.robjhyndman.com/forecast/reference/tsCV)

据此增加 EvaluationFold/FitSchedule；标准化、PCA、特征选择与阈值也需要独立 fit 证据。验证模型超参数时使用训练内部的选择安排或明确 development 范围，最终评价数据不能继续参与选择。这里只选择时间有序验证作为部署相似性的默认设计，不声称所有时间序列场景都禁止其他交叉验证。

### 反复试验和查看结果会改变证据含义

回测择优可能造成样本内表现与样本外表现脱节；PBO 文献给出了特定设计下的诊断方法。[Bailey 等原文](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf)

适应性数据分析研究也说明，反复基于结果选择下一项分析需要专门的有效性保障；可重复 holdout 有额外机制与假设。[Dwork 等原文](https://arxiv.org/abs/1506.02629)

本项目的设计推论是：保留跨批检验家族、访问记录与停止规则；单纯计数或增加一个 holdout 标签不足以修复偏差。当前不实现差分隐私 reusable holdout，不把 PBO 当成所有特征实验的默认统计检验。探索后冻结候选，使用尚未参与选择的后续范围确认；若反复查看，须预先采用适当序贯协议或保留探索性结论。

### 条件响应不是自动的因果效应

因果推断需要明确目标、识别假设及相应设计，不能仅由观测关联直接得到干预效果。[Hernán 与 Robins 作者书籍页](https://miguelhernan.org/whatifbook)

本项目默认把 event/regime 条件下的未来响应比较解释为关联或预测证据。将 H 称为 impact horizon 是沿用现有术语，其含义仍是响应期限；不因此声称市场冲击已被因果识别。若以后研究机制，必须另外说明处理、混杂、对照可比性及识别设计。

以上文献支持方法原则；领域对象划分及实施优先级是针对 QuantSage 的设计判断，并非这些文献直接规定的软件架构。

## 4. 一个贯穿例子

1. **A 批次**：选一周，计算 OBI 3s、30m 统计窗口中的少数 catch22；质量验证可到此结束，不需要未来标签。
2. **探索**：若研究极端 OBI 事件后的 1m 响应，先明确 Estimand、事件去重、对照、权重与价格单位；构建样本清单，按依赖设计不确定性估计。反复试阈值/窗口/H 都记入搜索家族。
3. **B 批次**：扩到一月，复用匹配结果，补算新日期；分别报告原周、新增日期、全月。新增日期是否可作为独立确认，取决于此前访问与候选冻结，不能只由“新增”推断。
4. **C 批次**：加入 tsfeatures，只计算选定新项；在相同范围比较消融结果，避免用样本构成变化冒充指标改进。
5. **确认与综合**：冻结候选和拟合计划，用未参与选择的后续区间评价；报告跨日期/合约异质性，综合所有相关正负结果。统计差异不足以证明成本后可执行收益。

## 5. 实施顺序与验收

先完成真实 Step 03–05 的数学/采样/有效性与依赖身份，再实现首个有 Estimand、样本清单和时间隔离的简单事件响应实验。通用状态模型、复杂搜索和知识网络均不应抢在这条可证伪闭环之前。

当前最小对象、接口与验收见 [简化领域模型](DOMAIN_MODEL.md)。以下科学验收在后续实验阶段适用，不阻塞当前画像管理工具。质量检查只能证明计算契约；科学验收还必须包括：未来数据扰动不改变历史输入/状态、fit 截止隔离、重叠样本识别、依赖结构下的零效应校准、选择/查看历史、跨时期复验及已知效应的受控模拟。
